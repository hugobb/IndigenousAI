# Technique guide

The MkDocs Material site that accompanies the atlas. Built from the literature
review; deployed at the site root, with the atlas served under `/atlas/`.

## Run it locally

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/mkdocs serve
```

A virtualenv rather than a system install: `mkdocs` is not a system dependency
of this repository, and `scripts/build-site.sh` creates the same `.venv` when it
builds.

## Build it

Do not run `mkdocs build` by hand for a deploy. `scripts/build-site.sh` at the
repository root is the one build command, and it does four things this directory
cannot do alone:

1. copies the 92 paper summaries in from `litterature_review/` — they are the
   source of truth and are never edited here,
2. builds this site,
3. builds the atlas into `atlas/`,
4. checks that **every route the atlas cites actually resolves**, and fails if
   one does not.

`site/` is build output and is gitignored. It was tracked until SP2b, which is
how 90 build artifacts came to be committed here.

`docs/summaries/` is generated by step 1 and also gitignored. Editing a file
there is pointless — the next build destroys it. Edit
`litterature_review/summaries/` instead.
