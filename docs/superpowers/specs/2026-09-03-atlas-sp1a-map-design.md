# Atlas SP1a — The map renders

**Date:** 2026-09-03
**Status:** Approved (design); plan not yet written
**Parent spec:** `2026-09-03-indigenous-nlp-atlas-design.md` — decisions D1–D9 and §3a bind this document. This spec **supersedes that spec's §6**, which still described the withdrawn Native Land polygon approach.
**Scope:** SP1a only. SP1b (facets, timeline, table, URL state) gets its own spec, written against a working map.

---

## 1. Purpose

Render the atlas: a map of Indigenous language NLP initiatives that tells the truth about its own coordinates.

SP1a ends with a map you can click. It does not filter, does not have a timeline, and has no table view — those are SP1b. The seam is real: SP1a is about **rendering honestly**, SP1b is about **querying**. They share only the shape of the record types.

## 2. Why this is split from SP1b

SP0 ran to ten tasks and needed four plan corrections mid-flight (a wrong pnpm setting, two arithmetic errors, a stale schema field). A single fourteen-task SP1 plan written before any pixel exists would need more, and a correction is cheapest before the plan is half-executed. Two plans of roughly eight tasks matches the size that worked.

SP1b's spec will also be materially better for being written against a map that exists — the same reasoning that deferred SP1 until SP0 landed, which paid off.

## 3. Decisions

| # | Decision | Rejected alternative and why |
| --- | --- | --- |
| E1 | **Build against a committed fixture bundle**, not real data. | Promoting the ten draft records first puts a careful research review — the step that genuinely needs human judgement — in front of all UI work. A `--include-drafts` bundler flag was rejected outright: a second code path into the bundle is exactly how a draft record eventually reaches a published figure. |
| E2 | **A record's location uncertainty is a schema field, not inferred from prose.** Add `confidence: 'sourced' \| 'approximate'` to `CentreSchema` and `SiteSchema`, defaulting to `'sourced'`. | `caveat` is free text: Myaamia's is about its centre, another record's might be about speaker counts. Rendering a pin as untrustworthy because of an unrelated caveat is its own dishonesty, and text-matching cannot fix that reliably. `caveat` remains the human-readable *why*. |
| E3 | **Uncertainty is visible on the map, not only in the detail panel.** | The map is what gets screenshotted and cited. At a glance a uniform dot would assert Masakhane is located in Nairobi — which its own record explicitly denies. Honest text one click behind a confident dot is not honesty. |
| E4 | **React + MapLibre GL.** | Vanilla TS ships one dependency and would still build in five years, but hand-wires filter state, URL sync and layer updates — where subtle bugs live, and SP1b needs all three. Svelte fits the problem best but is a third ecosystem in this repo. Preact+htm is clever and unusual, a poor trade in code meant to outlive its author's involvement. React is the most likely to be maintainable by someone who is not the author. |
| E5 | **Language presence is a large, heavily blurred `circle` layer.** No heatmap, no generated geometry. | The withdrawn design needed heatmap-over-sampled-polygon-grid. With one point per language, a blurred circle is the same result with less machinery. §3a of the parent spec forbids polygons regardless. |
| E6 | **`pnpm build` fails on a missing or empty `src/data/atlas.json`.** | Extends SP0's gate to the artifact a reader loads: you cannot build a publishable page from an empty bundle, and the bundle only ever contains `verified` records. |

## 4. The visual vocabulary

Each channel carries exactly one meaning. This is the spec's central constraint and the thing most likely to erode under later edits.

| Mark | Means | Encoding |
| --- | --- | --- |
| Large blurred circle | A language's approximate presence | Always soft, identically for every language. **The softness IS the "no boundary claim" statement and must never also encode confidence, size, or speaker count.** |
| Small crisp dot | An initiative | Indigenous tier filled; adjacent tier hollow (stroke only), so tier reads without a legend |
| Fuzzy, desaturated dot | An initiative whose record says its site is approximate | `circle-blur` — the pin is literally out of focus, which is what the record says |
| Desaturated field | A language whose centre is approximate | Desaturation, **not** extra blur; the language is also listed in an "approximate locations" affordance |
| Accent colour | Current selection | Default is one neutral ink for everything; selecting or hovering a language accents its field and drops the rest |

Selection is two MapLibre layers over **one** source, differing by `filter` — never two sources to keep in sync.

Basemap: CARTO Positron raster, no API key, attribution in-corner.

## 5. Architecture

```text
atlas/src/
├─ data/atlas.json              generated by SP0's bundler (gitignored)
├─ fixtures/atlas.fixture.json  committed; exercises the edges
├─ lib/
│  ├─ load.ts                   choose + shape-validate the bundle
│  └─ confidence.ts             PURE: sourced | approximate | absent
├─ map/
│  ├─ style.ts                  basemap style + layer definitions
│  ├─ layers.ts                 PURE: records -> two GeoJSON collections
│  └─ useMap.ts                 MapLibre lifecycle
├─ components/
│  ├─ App.tsx · MapView.tsx
│  └─ LanguagePanel.tsx · InitiativePanel.tsx
└─ main.tsx
```

**MapLibre is imperative; React owns state.** One `useMap` hook owns the map instance. Layer data updates through `source.setData()` — never by tearing down and recreating layers, which is how these integrations start flickering and leaking handlers.

**`layers.ts` is pure**: records in, two `FeatureCollection`s out (language centres, initiative sites). The hard part — which features exist, carrying which properties — is therefore unit-testable with no browser and no map instance.

## 6. Data flow

1. `load.ts` selects the bundle: fixture under `pnpm dev`, `src/data/atlas.json` under `pnpm build`.
2. It shape-validates and **fails loudly** on a missing or empty bundle (E6).
3. React holds `{ data, selection }`.
4. `layers.ts` derives two `FeatureCollection`s.
5. `useMap` pushes them via `source.setData()`.
6. Clicking a feature sets `selection`; the panel renders from the record, not from the map feature.

Step 6 matters: the panel reads the **record**, so it can show fields that never became map properties — conflicts, caveats, sources.

## 7. Panels

**Language:** name, alternate names, family, subfamily, typology, endangerment, speakers with conflicts, countries, centre with confidence and caveat, and the initiatives working on it.

**Initiative:** name, kind, tier, years (ongoing or ended), languages, applications, methods, models, data regime, governance, papers, links, site with confidence and caveat, and — for adjacent tier only — the transferability note.

Two rules:

- **An empty field renders as "not recorded", never as blank.** All five real languages have empty `typology` because nobody would assert one without a citation. A blank row reads as *nothing to say*; the words say *we don't know*. That distinction is why those fields were left empty.
- **Methods link into the mkdocs technique docs.** This is what makes the map an index into the guide rather than a standalone figure: a reader who sees a method on a pin clicks through to how to do it.

## 8. Fixtures

One committed `atlas.fixture.json`, hand-written to exercise what real data throws at us:

- a language with a researched (`sourced`) centre
- a language with an `approximate` centre and a caveat — modelled on Myaamia's round `(40.0, -90.0)`
- a language with `centre: null` — the "not mapped" path
- an adjacent-tier language, which carries no centre at all (D5)
- a language with a speaker-count conflict — modelled on Choctaw's 9,600 vs ~300
- an indigenous initiative, ongoing, `sourced` site
- an indigenous initiative that has ended
- an adjacent initiative with an `approximate` site and a transferability note — modelled on Masakhane
- an initiative referencing a real method id and paper id

## 9. Testing

- `layers.ts` — feature counts; null centres excluded; adjacent-tier languages produce no field; `approximate` records carry the properties the style keys on.
- `confidence.ts` — every branch.
- `load.ts` — shape validation; **the build refuses an empty bundle** (E6).
- One jsdom smoke test: the app mounts against the fixture with MapLibre mocked.
- MapLibre's rendering is not unit-tested.

## 10. Schema change this spec introduces

`confidence: 'sourced' | 'approximate'` on `CentreSchema` and `SiteSchema`, defaulting to `'sourced'`.

Then set `approximate` on the two real records whose own text already says so: `myaamia.yml`'s centre and `masakhane.yml`'s site. Both are `draft`, so no verified record is disturbed.

## 11. Explicitly NOT in SP1a

Facets, the range timeline, the table view, URL state — all SP1b. Deployment, the Zenodo DOI, and the stale Docusaurus references in `AGENTS.md` and `docs/README.md` — all SP2.
