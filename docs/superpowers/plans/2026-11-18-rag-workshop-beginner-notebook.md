# Beginner RAG Workshop Notebook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Colab notebook, `notebooks/rag_workshop_beginner.ipynb`, that walks people with no
coding background through RAG (embeddings → search → chunking → generation) using widgets, with
all code hidden behind Colab form cells.

**Architecture:** The notebook is *generated*. Its Python lives in three testable modules
(`content.py`, `toolkit.py`, `ui.py`) and its prose in one Markdown file per section.
`build_notebook.py` inlines the modules' source into hidden setup cells and interleaves the
Markdown with one-line `show_…()` form cells. Tests cover the pure logic, the content's claimed
effects on the real models, the widgets with a fake generator, and a headless execution of the
built notebook.

**Tech Stack:** Python 3.11+ (Colab), sentence-transformers (`all-MiniLM-L6-v2`), transformers
(`Qwen/Qwen3-1.7B`, CPU fallback `Qwen/Qwen3-0.6B`), ipywidgets, plotly, numpy; pytest, nbformat,
nbclient; `uv` to run everything locally.

**Spec:** `docs/superpowers/specs/2026-11-18-rag-workshop-beginner-notebook-design.md`

## Global Constraints

- All participant-facing text is in **English**, in plain language. Every technical term is defined
  in the sentence where it first appears.
- **No exercise requires editing code.** Every interaction is a widget.
- **Every code cell in the built notebook is a Colab form.** Its source starts with
  `#@title <Plain title> { display-mode: "form" }` and its metadata has `"cellView": "form"`.
- **No stack trace for a foreseeable failure.** No GPU, empty input, a section run before setup, a
  bad upload: each shows a plain-language message saying what to do.
- Generation uses **greedy decoding** (`do_sample=False`), `enable_thinking=False` and
  `max_new_tokens=200`. It runs **only on a button click**, never when a slider moves.
- Plots: render a plotly figure with `fig.show()` inside an `ipywidgets.Output`. **Never use
  `go.FigureWidget`**, which needs Colab's custom widget manager.
- The fictional document is **clearly non-Indigenous**, labelled fictional in the notebook, and
  invents no facts about real nations or organizations.
- No FAISS, HDF5 or disk caching. Embeddings live in memory.
- `notebooks/ollama_rag_workshop.ipynb` is **not modified**.
- Total time budget: 10 / 5 / 20 / 10 / 20 / 15 / 10 min for sections 0–6. Each section heading
  shows its time (e.g. `⏱ about 20 min`).
- Memory: any local run that loads Qwen goes through `memguard run --need 6G -- …`.

## Review Focus

1. **Overlap ≥ chunk size** (both sliders at their maximum) must not hang. Clamp the overlap to
   `size - 1`. The test is in Task 1.
2. **Empty or whitespace input** in any text box shows "Type a sentence first." (or a section-specific
   equivalent), never an error. Tests are in Task 4.
3. **Clicking "Ask" again while an answer is still being written** must not start a second
   generation. The button is disabled until the answer finishes. The test is in Task 4.
4. **A section cell run before the setup cell** prints "⚠️ Please run the Setup cell (section 0)
   first, then run this cell again." The test is in Task 5.
5. **An empty, non-UTF-8 or non-.txt upload** in the bonus section shows a plain message and skips
   that file. The test is in Task 4.

### Task 1: Toolkit pure logic

**Files:**
- Create: `notebooks/rag_workshop_beginner/requirements.txt`, `toolkit.py`, `tests/test_toolkit.py`,
  `tests/conftest.py` (adds the parent dir to `sys.path`), `pytest.ini` (registers the marker
  `llm: loads Qwen, slow`)

**Interfaces:**
- Produces (in `toolkit.py`):
  - `Strategy = Literal["fixed", "overlap", "sentences", "whole"]`
  - `split_sentences(text: str) -> list[str]` splits on `(?<=[.?!])\s+` and drops empties.
  - `chunk_fixed(text: str, size: int) -> list[str]` uses word windows.
  - `chunk_overlap(text: str, size: int, overlap: int) -> list[str]` clamps the overlap to
    `max(0, min(overlap, size - 1))`.
  - `chunk_sentences(text: str, n: int) -> list[str]`
  - `make_chunks(text: str, strategy: Strategy, size: int, overlap: int) -> list[str]`. For
    `sentences`, `size` is the number of sentences. `whole` returns `[text.strip()]`.
  - `cosine(a: np.ndarray, b: np.ndarray) -> float`
  - `similarity_label(score: float) -> str` returns `"very similar"` for ≥ 0.60,
    `"somewhat related"` for ≥ 0.40, `"loosely related"` for ≥ 0.20, and `"unrelated"` otherwise.
  - `rank(query_vec: np.ndarray, doc_vecs: np.ndarray, k: int) -> list[tuple[int, float]]`
    returns (index, score) sorted by descending score, with k capped at `len(doc_vecs)`.
  - `build_prompt(question: str, contexts: list[str], allow_unknown: bool) -> str`
  - `project_2d(vectors: np.ndarray) -> np.ndarray` does PCA with numpy SVD on centred vectors,
    giving shape `(n, 2)`. It handles n = 1 and n = 2 without NaN.

`build_prompt` uses this exact template (the participant sees this text in section 5):

```
Answer the question using the context below.
{if allow_unknown: "If the answer is not in the context, say \"I don't know based on these documents.\""}

Context:
[1] {contexts[0]}
[2] {contexts[1]}
…

Question: {question}
Answer:
```

### Task 2: Content and the retrieval effects it must show

**Files:**
- Create: `content.py`, `tests/test_effects.py`
- Modify: `toolkit.py` (add the embedder)

**Interfaces:**
- Produces (in `toolkit.py`): `class MiniLMEmbedder` with `embed(texts: list[str]) -> np.ndarray`.
  It returns L2-normalised rows using `sentence-transformers/all-MiniLM-L6-v2`, with the device
  passed in.
- Produces (in `content.py`):
  - `REPORT_TITLE: str` and `REPORT: str`: a fictional annual report of about 900–1,100 words, for
    example "Millbrook River Watch — 2025 Annual Report" (an invented town volunteer
    water-monitoring group). It is **non-Indigenous** and includes a sentence saying it is
    fictional. It has at least 5 specific facts (names, dates, numbers, a rule about who may access
    the raw records) at different points in the text.
  - `@dataclass QuestionSpec(question: str, keywords: list[str])`: the answer is "in" a chunk when
    every keyword occurs in it (case-insensitive).
  - `REPORT_QUESTIONS: list[QuestionSpec]` (4 items, the chunking dropdown). `SPLIT_QUESTION:
    QuestionSpec` is one of them: its keywords sit in **two consecutive sentences**, so a small
    chunk size separates them.
  - `PROBLEM_QUESTION: QuestionSpec` (sections 1 and 5) and `OUT_OF_DOC_QUESTION: str`
    (on-topic, but its answer is not in the report).
  - `DEMO_SMALL_SIZE: int`, `DEMO_OVERLAP: int` and `DEMO_GOOD_SIZE: int`: the values the "Try this"
    prose cites.
  - `PASSAGES: list[str]`: the 8 short real passages from `notebooks/ollama_rag_workshop.ipynb`
    cell 19, copied verbatim, except that the FAISS sentence in the vector-store passage is
    replaced with plain wording.
  - `SEARCH_EXAMPLE: str`: a question that retrieves the Kaitiakitanga passage first.
  - `SIMILARITY_PAIRS: list[tuple[str, str]]`: pair 0 has no shared content words but the same
    meaning (the data-sovereignty pair from the old notebook); pair 1 shares words but means
    different things (e.g. "The bank raised its rates." / "We sat on the river bank.").
  - `MAP_SENTENCES: list[tuple[str, str]]`: 16 sentences given as (sentence, topic), 4 topics × 4
    (e.g. rivers & water, food & cooking, data & privacy, cycling & sport).

### Task 3: Answer generation and the answer effects

**Files:**
- Modify: `toolkit.py`
- Create: `tests/test_llm_effects.py`

**Interfaces:**
- Consumes: `build_prompt`, `MiniLMEmbedder` and `content.*` from Tasks 1–2.
- Produces (in `toolkit.py`):
  - `class QwenGenerator(model_name: str, device: str)` with `generate(prompt: str) ->
    Iterator[str]`. It streams text pieces (`TextIteratorStreamer` plus a thread) using the
    Global Constraints settings and the chat template with `enable_thinking=False`. On CPU it loads
    in `torch.bfloat16`.
  - `class FakeGenerator` with `generate(prompt) -> Iterator[str]`. It yields
    `"(test answer) "` and then the first context line, word by word.
  - `@dataclass Models(embedder, generator, device: str, llm_name: str)`
  - `load_models() -> Models` picks `Qwen/Qwen3-1.7B` when `torch.cuda.is_available()` and
    `Qwen/Qwen3-0.6B` otherwise. If the env var `RAG_WORKSHOP_FAKE_LLM=1` is set it uses
    `FakeGenerator`, and if `RAG_WORKSHOP_LLM` is set it uses that model name instead.
  - `status_line(device: str) -> str`, with the exact copy:
    - cuda: `"✅ Ready — using the GPU. Answers take a few seconds."`
    - cpu: `"⚠️ Ready, but without a GPU: answers will be slow and a bit less accurate. To fix it: menu Runtime → Change runtime type → T4 GPU → Save, then run this cell again."`
  - `answer(models: Models, question: str, contexts: list[str], allow_unknown: bool) -> Iterator[str]`

### Task 4: Widgets for each section

**Files:**
- Create: `ui.py`, `tests/test_ui.py`

**Interfaces:**
- Consumes: everything in `toolkit.py` and `content.py`.
- Produces (in `ui.py`). Each `show_*` builds and `display()`s its widget box **and returns it**,
  so tests can drive it:
  - `show_problem(m: Models)`: a fixed question (`PROBLEM_QUESTION`) and an "Ask the model" button
    → the streamed answer.
  - `show_similarity(m)`: two text boxes prefilled with `SIMILARITY_PAIRS[0]`, a "Compare" button,
    and a pair dropdown → a score bar (0–1 HTML bar) plus `similarity_label`.
  - `show_meaning_map(m)`: a plotly scatter of `project_2d` over `MAP_SENTENCES`, coloured by topic,
    with hover text showing the sentence. A text box and "Add to map" button add a point coloured
    "your sentences". A "Reset" button clears it.
  - `show_search(m)`: a question box prefilled with `SEARCH_EXAMPLE` and a "Search" button →
    all `PASSAGES` ranked with score bars (top 3 highlighted).
  - `show_chunking(m)`: a strategy dropdown (labels "Fixed size", "Fixed size with overlap",
    "By sentences", "Whole document — no chunking"), a size slider (10–200 words, step 5; for
    sentences, 1–10), an overlap slider (0–50, disabled unless overlap is chosen) and a question
    dropdown (`REPORT_QUESTIONS`). It updates **live** on every change: a chunk count, the report
    with chunks shown in alternating background colours (overlap words in a third colour), and the
    top chunk with its score. An "Ask the model with this chunk" button → the streamed answer.
  - `show_generation(m)`: a question box (prefilled `PROBLEM_QUESTION`), a top-k slider (1–5), an
    "allow 'I don't know'" checkbox (default on) and an "Ask" button. It shows the exact
    `build_prompt` text (the context part highlighted), then the RAG answer and the no-RAG answer
    side by side (two columns; they stack on narrow screens).
  - `show_upload(m)`: Colab → `google.colab.files.upload()` behind a button; elsewhere → a
    `FileUpload` widget. Chunks at `DEMO_GOOD_SIZE` with overlap `DEMO_OVERLAP`, then a question box
    and "Ask".
  - `ensure_ready() -> bool`: True when `MODELS` exists in `__main__`. Otherwise it prints the
    Review Focus 4 message.
  - Every "Ask"-type button is disabled while its answer streams, then re-enabled.
